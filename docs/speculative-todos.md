# Speculative TODOs

Unvetted ideas from a 2026-08-14 review of the documentation-and-verification system, saved so they need not be re-derived. None is a commitment, none has been costed beyond a sentence, and any may die to a measurement — when one does, record the ruling here so it is not re-proposed. The common thread: convert remembered discipline into mechanism that fires, since the recorded failures of this system — the unwrap-rewrap cycle, the rules file that never loaded, the stamp that sat orphaned for eleven days — are each a case of remembered discipline failing while every mechanical check stayed green. Scope varies by item: some are this repo's, some user-scope, some span the repos sharing the tools.

1. **Anchor citations to content, not line numbers.** The prose rule already exists ("carry a distinctive phrase; a line number does not survive a reflow") — apply it to code citations. Store the expected snippet, or its hash, with each `file:line` and let `tools/check-plan-citations.py` compare rather than merely resolve; or replace line numbers with unique anchor strings the checker locates. This closes the "a citation that resolves can still lie" class mechanically — today the eyeballing of printed snippets is the one part of pass 1 still resting on a reader — and a legitimate drift then flags for restamp instead of passing silently. Small effort, probably the largest remaining accuracy hole.

2. **Make claims executable where they are checkable.** Pass 3 is expensive because quantified claims live as prose and every verification re-derives the greps. Attach the evidence to the claim: an inline check block (command plus expected result) beside each only/every/count claim, and a runner that executes them all — `tools/check-doc-examples.py`'s `>>>` mechanism generalized from Haskell outputs to arbitrary claims. Stamps then become per-claim, drift cannot be silent, and the human reading shrinks to the unmechanizable residue. The six-counts-falsified-in-a-day incident is the case this answers.

3. **Fire rulings and lazy context from hooks, not path frontmatter.** The path-keyed load is measured-undependable and nothing announces its absence; hooks are deterministic. A PreToolUse hook matching edits under the performance-relevant modules can inject a one-line pointer to `.claude/rules/performance-model.md` with certainty, and the don't-do rulings — whose whole purpose is firing at the moment of re-proposal — could live in a small pattern-to-ruling table a hook greps against commands and diffs (gather fusion, `-A64m`, `--no-gpg-sign`, `stash pop`), surfacing the one-line ruling exactly when someone starts to violate it. Tripwires beat residency on both probability and token cost. User-scope mechanism; amends the migration ruling's *mechanism*, not the ruling.

4. **Verify at the events that cause rot, not on request.** Stamps orphan at rebases, twins drift at edits, claims rot at pushes — hang the checks there: a `post-rewrite` git hook running the stamp check, `pre-push` running the checker suite and the self-tests (seconds, now that they exist), and a periodic doctor session for the sampled deep passes. The orphaned bench stamp would have been caught the minute of the squash.

5. **Re-measure the environment almanac instead of trusting it.** The portable notes are largely executable facts — `pkill` self-matching, the phantom dotfiles, `gpg` under the sandbox, the ugrep shim's quirks. One environment-selftest script probing the top facts, run occasionally and on Claude Code version changes, gives the machine notes what the checkers got: a control that cannot expire silently. Today they have no instrument at all and break invisibly on harness updates.

6. **Mechanize the printed-AST oracle into affected-set benchmarking.** The "can this rewrite affect that program" trick is the cheapest decisive instrument in the performance model, applied by hand. A script printing the canonical artifacts of the benchmark suite's programs under both builds and diffing them would settle affects-nothing claims in one command and shrink collections to the affected set — most of a long `convVjpBench` run avoided when churn is localized. Pairs with committing measurements as JSON artifacts that prose cites by ID, dissolving the provenance clauses the cost-facts bullets used to carry.

7. **Stop having twin tools.** `tools/check-twin-sync.py` patches the symptom; the cause is vendored copies. The isolated config blocks are most of the packaging work already done: one shared doc-tools sibling checkout on the model of `../ox-arrays`, with per-repo config files, ends the porting debt permanently and retires the sync checker.

8. **Test the guidance itself, so the corpus can shrink.** The user-scope `CLAUDE.md` is a layer that dies with each model generation, but it only grows. Point the blind-walk instrument at rules: run a fresh session through a recorded failure scenario without the bullet and see whether the current model still errs; a bullet the model no longer needs retires with evidence. Residency is the system's largest recurring cost and this is its only principled deletion mechanism so far.

9. **A CI step running the citation checker.** Of the mechanical passes, `tools/check-plan-citations.py` is the one CI can run — self-contained on git and the tree, needing neither the sibling checkouts nor wrap80 — so a seconds-cheap step in `lint-and-test-suites.yml` over the stamped documents would catch an orphaned or stale stamp at push time, from any machine. This is the narrow, do-now member of item 4's family: the git-hook variants cover only the machine that installs them.

If only two: item 1 for accuracy per unit effort, item 3 for making the anti-re-proposal goal — the one the rulings genre exists for — nearly deterministic.
